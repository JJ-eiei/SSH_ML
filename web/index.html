รูปแบบไฟล์ที่รองรับ (CSV หรือ auth.log ของ OpenSSH)

1) CSV

แถวแรกต้องเป็นชื่อคอลัมน์ (สะกดตรงตัว ตัวพิมพ์เล็ก/ใหญ่มีผล) — ต้องมี 5 คอลัมน์นี้ ลำดับไม่สำคัญ คอลัมน์อื่นจะถูกข้าม

คอลัมน์ค่า
Timestampเช่น 2026-10-06 14:03:21 หรือ 2026-10-06T14:03:21.123 (ใช้เขตเวลาเดียวกันทั้งไฟล์)
Eventหนึ่งใน Failed password, Invalid user, Accepted password, Accepted publickey
Usernameชื่อบัญชีที่ถูกลอง
Source_IPIP ต้นทาง
Source_Portport ต้นทาง (ตัวเลข)

1 แถว = 1 ครั้งที่พยายาม login · Event อื่นจะถูกนับเป็นแถวแต่ไม่นับเป็น fail/success จึงควรกรองออกก่อน

Timestamp,Event,Username,Source_IP,Source_Port

2) auth.log ของ sshd (อัปโหลดไฟล์ดิบได้เลย)

เว็บแปลงเป็น CSV ให้ในเบราว์เซอร์ อ่านเฉพาะบรรทัดของ sshd ส่วนบรรทัดอื่น (CRON, pam_unix, Disconnected ฯลฯ) จะถูกข้าม

Oct  6 14:03:21 web01 sshd[1201]: Failed password for root from 203.0.113.9 port 51022 ssh2
Oct  6 14:03:25 web01 sshd[1201]: Failed password for invalid user admin from 203.0.113.9 port 51031 ssh2
Oct  6 14:05:40 web01 sshd[1230]: Accepted publickey for jj from 192.0.2.44 port 53320 ssh2: ED25519 ...
2026-10-06T14:07:01+07:00 web01 sshd[1400]: Accepted password for jj from 192.0.2.50 port 60000 ssh2

วิธีดึงไฟล์จาก server (Ubuntu/Debian):

sudo grep sshd /var/log/auth.log > ssh.log
# หรือ
journalctl -u ssh --since "30 days ago" -o short-iso > ssh.log

RHEL/CentOS ใช้ /var/log/secure และ unit ชื่อ sshd · บรรทัดแบบ syslog ไม่มีปี เว็บจะใช้ปีปัจจุบัน · ฟีเจอร์ระดับ IP คำนวณจากทั้งไฟล์ ไฟล์ที่ครอบคลุมหลายวัน (เช่น 30 วันแบบตอนเทรน) จะให้ผลใกล้เคียงที่วัดไว้ที่สุด · เมื่อใช้ backend ไฟล์ที่แปลงแล้ว (CSV) จะถูกส่งไปประมวลผลที่ server ของเรา

สร้าง log ทดสอบใหม่ ไม่ซ้ำกับชุดทดสอบ

สุ่มสร้าง log ใหม่ทุกครั้งตามพฤติกรรมที่เลือก (IP, เวลา, port, จำนวนครั้ง สุ่มใหม่หมด และไม่ใช้ IP ของไฟล์ทดสอบ 10 ชุด) ไฟล์ที่ส่งให้โมเดลไม่มีเฉลย — เฉลยเก็บแยกไว้ใช้ตรวจหลังวิเคราะห์

พฤติกรรมใน log สร้างด้วยกฎเดียวกับข้อมูลที่ใช้เทรน แต่สุ่มค่าใหม่ทั้งหมด — ทดสอบได้ว่าระบบทั้งหมดทำงานถูกกับข้อมูลที่ไม่เคยเห็น (ยังไม่ใช่การทดสอบกับ log จริงจาก server — ใช้ auth.log ของจริงได้ที่ช่องอัปโหลดด้านบน)

ชุดไฟล์ทดสอบ (10 ไฟล์)

ลากการ์ดด้านล่างไปวางที่ช่องอัปโหลดด้านบนได้เลย หรือกด "โหลดเข้าเครื่องมือ" (รันผ่านโมเดลทันที) / "ดาวน์โหลด" (เซฟไฟล์ลงเครื่อง) — 3 ไฟล์สุดท้ายต้องใช้ฟีเจอร์ระดับ IP / ข้าม IP ถึงจะเห็น

SAFE

Baseline ปกติ

Login สำเร็จของพนักงานหลายคน หลาย IP ไม่มี fail เลย — เช็ค false positive พื้นฐาน

ดาวน์โหลด
HARD NEGATIVE

User พิมพ์รหัสผิดบ่อย

user จริงพิมพ์รหัสผิดหลายครั้งก่อนสำเร็จ — ต้องไม่ over-flag คนขี้ลืมรหัส

ดาวน์โหลด
HARD NEGATIVE · NEW

User Roaming หลาย IP

user คนเดียว login สำเร็จจากหลาย IP ในเวลาไม่กี่ชั่วโมง (มือถือ/ทำงานนอกสถานที่) — "หลาย IP" อย่างเดียวไม่ควรแปลว่าน่าสงสัย

ดาวน์โหลด
HARD NEGATIVE

Shared-IP Office/NAT

IP office เดียว หลายคน login สำเร็จ — ต้องไม่ถูก flag ทั้งที่ username หลากหลายบน IP เดียว

ดาวน์โหลด
ATTACK

Burst Brute Force (ชัดเจน)

IP เดียวยิง failed password รัวๆ ใส่ account เดียว ไม่มี success เลย — ควรจับได้เกือบ 100%

ดาวน์โหลด
ATTACK

Focused Brute Force

หลาย password ถูกยิงใส่ account เดียว จำนวน fail/จังหวะเวลาจงใจให้ใกล้เคียงกับ user ที่พิมพ์ผิดจริง — โมเดลต้องแยกจากพฤติกรรมรวม ไม่ใช่แค่นับ fail

ดาวน์โหลด
ATTACK

Password Spraying

password ที่ใช้บ่อยไม่กี่ตัว กระจายยิงใส่หลาย username จาก IP เดียวหรือไม่กี่ IP

ดาวน์โหลด
ATTACK · NEW

Credential Stuffing

ใช้คู่ username:password ที่ "รู้อยู่แล้ว" (leaked credentials) — fail ต่อ account น้อยกว่าการเดาสุ่มมาก สำเร็จปนอยู่กลางๆ ไม่ใช่ท้ายสุด

ดาวน์โหลด
ATTACK · NEW

Persistent Multi-day (Stealth)

IP เดิมกลับมาซ้ำๆ ~30 sessions กระจายกว่า 2 สัปดาห์ แต่ละ session สั้น/fail น้อยจนดูไม่น่าสงสัยทีละครั้ง — ต้องอาศัย IP-level feature (จำนวน session สะสม/ช่วงวันที่ยังโผล่มา) ถึงจะเห็นภาพรวม ฟีเจอร์ระดับ session อย่างเดียวจับไม่ได้

ดาวน์โหลด
ATTACK · NEW

Coordinated Botnet Spike

~25 IP ต่างกัน ยิง account เป้าหมายเดียวกันพร้อมกันภายในไม่กี่นาที แต่ละ IP เองดูเหมือน burst เล็กๆ ทั่วไป — ต้องอาศัย cross-IP time-window feature (จำนวน IP อื่นที่ยิง target เดียวกันในกรอบ 15 นาที) ถึงจะเห็นการประสานงาน
